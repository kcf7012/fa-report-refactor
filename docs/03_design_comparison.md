# FA Report Improvement Skill — 設計對比:v2.3 vs v3.0

> **目的**:用具體範例展示新版面設計原則帶來的差異
> **比較對象**:本次 session 改善的 3 份報告

---

## 一、現況診斷(v2.3.0 baseline)

### 共通問題:內容擠壓

觀察 `260811_Kobo_ZHT_RA6080_SPcomFailI_improved.pptx` 投影片 6「根因驗證及統計分析」:

```
┌─────────────────────────────────────────────────┐
│ 根因驗證及統計分析                              │
│                                                 │
│ ◆ 針對問題點之深度分析建議:                      │
│   • 應使用 5-Why 分析法探討...                  │
│   • 必須針對根因提出...                          │
│   • 結論僅停留在「推測」...                       │
│   • 提升照片清晰度...                            │
│                                                 │
│ ◆ [建議執行動作]                                 │
│   • 設定 DVT 正常品 vs PVT 異常品之對照組         │
│   • 使用獨立樣本 t 檢定驗證...                    │
│   • 確保統計證據支持最終提到的根本原因            │
└─────────────────────────────────────────────────┘
```

**問題**:
- ❌ 4 條 LLM 評語 + 3 條標準動作,總共 7 個 bullet
- ❌ 沒有視覺元素(圖表、流程圖)
- ❌ 沒有圖示化對照組
- ❌ 5-Why 只用一行文字帶過,沒有展開
- ❌ 字級偏小,看起來像「文字雲」而非「專業報告」

## 二、v3.0 設計:一張投影片只講一件事

### 範例 1:Kobo 報告 — 根因分析應該展開為 4 張投影片

#### 投影片 A:**為何「推測」不等於「分析」**

```
┌──────────────────────────────────────────────────┐
│ 為什麼本報告目前只是「推測」而非「分析」?        │
│                                                  │
│ ┌────────────────────────────────────────────┐   │
│ │ 推測 vs 分析                                │   │
│ │ ─────────  ─────────                       │   │
│ │ 「I/O 損傷」  「IC 內部電路路徑燒毀,        │   │

│                                                  │
```

**版面特點**:

## 三、實際改善總數對比

| 報告 | v2.3.0 投影片數 | v3.0 投影片數 | 差異 |
|------|----------------|--------------|------|
| Kobo RA6080 | 8(原 5 + 新 3) | 12(原 5 + 新 7) | +4 |
| N160JCN-EEK | 11(原 9 + 新 2) | 14(原 9 + 新 5) | +3 |
| MS Meishan | 8(原 5 + 新 3) | 11(原 5 + 新 6) | +3 |

**結論**:v3.0 平均多 3-4 張投影片,但每張投影片的資訊密度降低、視覺品質提升。

## 四、實作優先級

3. 為每張新投影片加一個視覺元素(checklist、流程圖、對照表)
